# MyLedger 数据导入方案

> 目标：每个月把自己的账单导进来，看清钱花在哪。
> 约束：完全本地运行、不泄露、少出错、不重复记账。
>
> 最后更新：2026-10-04

---

## 0. 结论

**一条流水线，四道闸门，AI 只用在它擅长的地方。**

```
原始文件(带密码zip/CSV/XLSX/截图)
   ↓  ① 格式嗅探：不认列号，认列名  ← 抗改版
   ↓  ② 标准化：统一成 Txn（金额/时间/方向）
   ↓  ③ 三层去重：只有第一层自动丢，其余交人确认  ← 防重复
   ↓  ④ 分类：规则优先，本地 AI 兜底
   ↓
SQLite（在 vault 里，仓库外）→ 月报
```

三个最关键的决定：

1. **去重绝不用 AI。** 「这两笔是不是同一笔」是确定性判断，用规则做，可复现、可解释。AI 一旦误判，你连它为什么删了那笔都不知道。
2. **只对「同源 + 同单号」自动去重。** 其余一律标记待确认，不自动删除。跨渠道的同一笔支出和「同一分钟买了两杯咖啡」在数据上无法区分，机器没有资格替你决定。
3. **本地 OCR 处理银行截图。** Windows 自带 OCR 引擎，中文可用、零安装、零联网。云端 OCR 会把你的银行卡流水上传，这是本方案唯一的红线。

## 1. 数据源现状（实测，不是猜的）

### 支付宝交易明细

导出自：支付宝 → 我的 → 账单 → 右上角「…」→ 开具交易流水证明 → 用于个人对账。

| 项 | 实测值 |
|---|---|
| 下载形式 | **带密码的 zip**（密码是你申请时设的） |
| 内部文件 | `支付宝交易明细(...).csv`，约 21 KB / 119 笔 |
| 编码 | **UTF-8 带 BOM**（用普通 utf-8 解会在首格残留 `\ufeff`，导致表头匹配失败） |
| 换行 | LF |
| 说明行 | 第 1–23 行是导出说明，**第 24 行才是表头**（行数会随版本变，所以不能写死） |

表头（12 列）：

```
交易时间,交易分类,交易对方,对方账号,商品说明,收/支,金额,
收/付款方式,交易状态,交易订单号,商家订单号,备注
```

### 微信支付账单流水

导出自：微信 → 我 → 服务 → 钱包 → 账单 → 右上角「常见问题」→ 下载账单 → 用于个人对账 → 选时间范围 → 填邮箱。

| 项 | 实测值 |
|---|---|
| 下载形式 | **带密码的 zip**，发到邮箱；密码在微信里单独给你 |
| 内部文件 | `.xlsx` |
| 编码 | xlsx 内部是 UTF-8 XML；交易时间是文本字符串 |
| 说明行 | 第 1–14 行是导出说明，**第 15 行才是表头** |
| 说明行的金额 | 写作 `!!!!!!!!!!` 之类（导出方自己的处理），不影响解析 |

表头（11 列）：

```
交易时间,交易类型,交易对方,商品,收/支,金额(元),支付方式,
当前状态,交易单号,商户单号,备注
```

金额列写作 `¥28.50` 形式（带货币符号），解析器要能剥掉。

### 银行卡

**首选：加密 PDF。** 有些银行支持「发送账单到邮箱 / 导出交易明细」，导出的是加密 PDF。
这是最靠谱的一条路，原因很直接：

| | 截图 + OCR | 加密 PDF |
|---|---|---|
| 文字来源 | 靠引擎**猜**字形 | 结构化存储，**精确字符** |
| 出错方式 | 糊一个字符，金额就错，且不报错 | 不会读错 |
| 坐标 | 靠 OCR 估 | 精确，能还原列 |
| 日期 | **实测整列读不出来** | 正常读出 |

导入方式：PDF 丢进 `inbox\`，跑 `monthly.cmd`，提示时输一次密码（用完即忘）。

**兜底：截图 + 本地 OCR。** 银行 APP 没有导出功能时才走这条。
截图要求：

- 用银行 APP 的「交易明细」页，**不要**用首页的缩略列表（那条没有时间/对方字段）
- **一屏一张图，别用滚动截长图。** 长截图每笔占的像素太少，
  实测一张 1216×9456 的长图，OCR 连一个冒号、一个日期分隔符都没读出来
- 每笔交易至少能看到：时间、交易对方、金额、收支方向

> 关于截图这条路的结论：**能自动读金额，读不出日期**。没有日期就没有月份归属，
> 记进去等于把月报表搞错，所以导入器会在解析到 0 笔时直接拒绝。
> 遇到这种情况请改用 PDF 导出，或者放大后分屏截图。

### 一个必须知道的失败模式

**导出文件可能是残缺的——只有说明和表头，没有流水行。**

一份 9.5 KB 的微信 xlsx 里可能只有 16 行、38 个单元格，说明里却写着「共 87 笔记录」。

如果导入器不做校验，它会安安静静地写进一个空批次，你月底看到「本月零支出」，还以为自己这个月没花钱。

**所以导入器有一条硬规则：解析到 0 笔就报错退出，不写库，并对比文件自述的笔数。** 这是整个方案里唯一一条「宁可失败也不能继续」的规则。

## 2. 为什么按列名匹配而不是按列号

两家平台的导出格式每隔一两年就会改一次。如果代码写死「金额在第 6 列」，改版后不会报错，只会把金额读到备注列上——**静默的错误比报错危险一个数量级**。

所以解析器不认列号，只做三件事：

1. 按编码优先级尝试解码
2. 用关键词（`交易时间`/`金额`/`收/支` 至少命中 2 个）扫出真正的表头行，跳过说明行
3. 按列名别名表反查下标

改版时只需要往别名表里加一个名字，逻辑不动。

## 3. 去重：三层，只有一层允许自动丢弃

| 层 | 判据 | 处置 | 为什么 |
|---|---|---|---|
| **L1** | 同源 + 同交易单号 | **自动跳过** | 这就是同一条记录。重复导入同一个文件天然幂等 |
| **L2** | 时间(到分) + 金额 + 交易对方 完全一致，但单号不同 | 标记 `suspect_exact`，**不删** | 可能是支付宝和银行卡各记了一次的同一笔支出 |
| **L3** | 金额相同 + 时间相差 ≤5 分钟 + 对方相似度 ≥60% | 标记 `suspect_near`，**不删** | 数据上无法区分「跨渠道重复」和「真的买了两杯咖啡」 |

为什么 L2/L3 不自动合并：

- 同一笔支出在支付宝扣款、银行流水也会有一条，两个渠道的单号不同、金额时间和商户一致——这就是 L2。
- 但「同一分钟在同一家便利店买了两瓶水」长得分毫不差。
- 这两种情况在数据上完全不可区分。**机器标记，人做决定。**

人工处置：

```bash
python -m importer review                    # 逐条看，两笔并排显示
python -m importer review --resolve 12 --as dup   # 确是同一笔，从统计中剔除
python -m importer review --resolve 12 --as ok    # 是两笔独立交易，不再提示
```

被标记为 `confirmed_dup` 的记录不删除，只是从统计里剔除。`--resolve` 执行前会先把目标记录打印出来让你确认——打错一个 id 就把一笔真实消费从报表里抹掉，这种错不留痕迹，最难查。

**去重不碰 AI。** 见开头。

## 4. AI 用在哪，不用在哪

| 任务 | 用什么 | 理由 |
|---|---|---|
| 解析字段、算金额、判方向 | 规则 | 精确逻辑，必须可复现 |
| 找表头、跳过说明行 | 规则 | 同上 |
| 去重判定 | 规则 | 见第 3 节 |
| **商户名 → 消费分类** | 规则优先，**本地 AI 兜底** | 真的模糊：「某某网络科技有限公司」是干什么的，规则答不上来 |
| **银行截图文字 → 结构化行** | 本地 OCR + 规则，AI 兜底 | OCR 出的是乱文本，需要语义理解才能拆成字段 |

AI 的三条硬约束（写在代码里，不是口头承诺）：

1. **只能连 `127.0.0.1` / `localhost`。** `categorize._assert_local()` 会直接拒绝任何外部主机名。整个工具不允许任何形式的联网。
2. **必须插电。** 跑本地模型是 CPU/GPU 密集任务。未插电直接跳过并说明原因，`--ignore-power` 可强制。本机实测满电续航约 2.7 小时，一小时满载吃掉近半块电池，拿这个换一次分类不值。
3. **结果缓存。** 同一个商户只问一次，写进 `merchant_category` 表。下次连模型都不用开——省电、可离线、结果稳定。

启用方式：

```bash
# 一次性的：装 Ollama 并拉一个中文模型
ollama pull qwen2.5:7b

# 之后导入时加 --ai
python -m importer import <账单> --ai
```

没装 Ollama 也能正常用，规则能覆盖大部分常见商户。

## 5. 银行卡截图：本地 OCR

```bash
python -m importer ocr 截图1.png 截图2.png
# 输出到 %USERPROFILE%\MyLedgerVault\ocr\
#   <名字>.raw.txt     OCR 原始文本行
#   <名字>.rows.tsv    按坐标重组的行（可直接喂给导入器）
#   <名字>.ocr.log     识别统计

python -m importer import "%USERPROFILE%\MyLedgerVault\ocr\*.rows.tsv" --source bank
```

**为什么要把 OCR 结果按坐标重组：** 银行 APP 的交易明细是横向一行一条。OCR 只会按视觉顺序吐出文字片段，直接拼起来就丢掉了「哪个金额属于哪个商户」的对应关系。脚本用每个词的边界框把同一水平线上的片段聚成一行、再按 x 排序，还原出「时间 | 商户 | 金额」的行结构。

用的是 `Windows.Media.Ocr`（Windows 10/11 自带，支持中文），不装任何东西、不上传任何图片。

**第一次用请人工核对前几行。** 各家银行的字段顺序不同，而且 OCR 错一个数字不会报错，只会让你的月支出悄悄多出一笔。

命令：

```bash
python -m importer monthly                  # 月度批处理（推荐）
python -m importer review --ui              # 疑似重复确认：两个大按钮（推荐）
python -m importer review                   # 同上，但输出在终端里
python -m importer import <文件> [--password 密码] [--dry-run]
python -m importer report [--month 2026-09]
python -m importer store                    # 查看账本加密状态
python -m importer sources                  # 各渠道导出方法速查
python -m importer ocr <图片...>

# PDF 结构探针（换银行时先跑这个，输出全部脱敏，可安全外发）
<venv>\Scripts\python.exe scripts\bank-pdf-probe.py "账单.pdf"

# 所有命令都支持 --vault <目录> 指定 vault 位置（默认 %USERPROFILE%\MyLedgerVault）
```

**关于依赖**：整条链路原本是纯标准库。PDF 那一步做不到——PDF 解密必须有库。
所以引入了 **PyMuPDF**（装在隔离 venv 里，不碰系统 Python），并配了 **pypdf** 作备选。
其余部分仍然是纯标准库。`scripts\monthly.cmd` 会优先用带这两个库的解释器。

只要标准库，不依赖任何第三方包——本地隐私工具装一堆第三方包本身就是额外的供应链风险。

## 7. 每月操作流程（已自动化到「只动手，不动脑」）

### 7.1 先划清边界

| 步骤 | 能不能自动 | 为什么 |
|---|---|---|
| 导出支付宝 / 微信账单 | ❌ **不能** | 两家都没有 API。必须你在手机 APP 里申请，微信还会发到邮箱 |
| 截银行 APP 的交易明细 | ❌ **不能** | 银行 APP 没有导出功能，也没法脚本化截图 |
| 解压 → 解析 → 标准化 | ✅ 能 | 纯本地逻辑 |
| 去重 | ✅ 能 | 确定性规则 |
| 分类 | ✅ 能 | 规则优先，结果有缓存 |
| 归档原始文件 | ✅ 能 | 复制进 vault |
| 出月报 | ✅ 能 | — |
| **裁定疑似重复** | ❌ **不该自动** | 唯一需要人判断的地方。自动化的代价是可能误删真实消费 |

**结论：能自动的是「文件到手之后」的全部工作；拿文件那一步只能你自己动手。**
这不是技术缺陷，是这两家平台的现实。

### 7.2 一次性准备

```powershell
# 1. 装提交闸门（如果还没装）
scripts\setup.cmd

# 2. 装自动触发（登录时跑一次，不需要管理员权限）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\schedule-monthly.ps1 -Action register
```

没有密码要设置——**本程序不保存你的 zip 解压密码**（见 7.5）。

### 7.3 每月你要做的（只有两步）

```
1. 三个渠道导出账单，全部丢进 %USERPROFILE%\MyLedgerVault\inbox\
   （银行截图先跑一次：python -m importer ocr 截图1.png 截图2.png
     再把输出的 *.rows.tsv 丢进 inbox）

2. 双击 scripts\monthly.cmd
   → 遇到加密 zip 会提示输一次密码，用完即忘
   → 处理完如果发现疑似重复，**自动弹出确认界面**，点完两个大按钮即可
```

也就是说：**交互式跑的时候不用另外敲 review 命令**，monthly 发现疑似重复会自己把界面拉起来。

后台运行不会弹（没人在场，弹窗口只会干扰），它只提示你「登录后手动跑一次」。

想关掉自动弹窗：`python -m importer monthly --no-review`。

这一步别跳过——**它是全流程唯一能挡住重复记账的地方**。手动补跑：

```
python -m importer review --ui
```

### 7.4 自动化是怎么触发的

默认用**登录时触发**（在「启动」文件夹放一个快捷方式），不是定时任务。

理由：这条流水线是**幂等**的——同一份文件重复导入不会重复记账（L1 按「同源 + 同交易单号」跳过），
所以「跑得频繁」零副作用。登录触发比定时触发可靠得多，笔记本也不存在「到点关机就跳过」的问题，
更不会为了跑一个几秒钟的脚本去唤醒机器。

想改成每天定时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\schedule-monthly.ps1 -Action register -Daily -Time 09:00
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\schedule-monthly.ps1 -Action status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\schedule-monthly.ps1 -Action remove
```

后台运行的输出会追加到 `%USERPROFILE%\MyLedgerVault\logs\monthly-YYYYMM.log`。
**自动化的日志是必需品**——没人在旁边看的时候，出问题你只有这份日志可查。

### 7.5 关于密码：只输一次，用完即忘

**本程序不保存你的 zip 解压密码。** 交互式运行（双击 `monthly.cmd`）时，
每个渠道提示输入一次，输完立刻从内存丢弃——不写文件、不留缓存、不进日志。

**这带来一个必须接受的后果：后台自动运行处理不了加密 zip。**

```
后台任务启动
  ├── 已解压的 csv / xlsx  → 正常导入（这些文件本来就没有密码）
  └── 加密 zip             → 跳过，留在原地并提示「登录后手动跑一次 monthly.cmd」
```

这是「不记密码」的必然结果，不是缺陷。两条路选一条：

| 想要的效果 | 怎么做 |
|---|---|
| 后台全自动 | 自己解压出 csv，把 csv 丢进投递目录 |
| 省事（zip 直接丢） | 保持现状，每月手动双击一次 `monthly.cmd` 输密码 |

代码上这条约束是硬编码的：`credentials.py` 里除了 DPAPI 加解密，
**根本不提供「保存密码」这个能力**——不给的能力就不会被误用。

### 7.6 账号数据怎么存的：加密落盘，明文不碰硬盘

账本不是普通 SQLite 文件，是加密的。做法：

```
打开：读 ledger.db.enc → DPAPI 解密 → 装进内存 → 全程在内存里操作
退出：从内存序列化 → DPAPI 加密 → 原子写回 ledger.db.enc
```

三个关键点：

1. **明文一秒都不落盘。** 不是「加密文件 + 运行时解密到临时文件」那套——
   那套会在硬盘上留下明文副本，恰好是要防的东西。内存方案没有这个窗口。
2. **没有第三方依赖。** 没有 SQLCipher，也没有自己手写的 AES。DPAPI 是操作系统提供的。
3. **不用再记一个密码。** 你已经明确要求 zip 密码用完即忘，再让你记一个数据库密码是自相矛盾的。

**代价必须知道：** 密钥由 Windows 用户账户派生，所以**重装系统或换 Windows 账户后这个库解不开**。
兜底手段是 `vault\raw\` 里的原始账单归档——真出事了重新导一遍即可。

查看存储状态：

```bash
python -m importer store
```

它会明确告诉你加密库在哪、多大，以及是否存在遗留的明文库（有的话会催你删掉）。

### 7.7 裁定界面：两个大按钮

```bash
python -m importer review --ui
```

终端里做不到「按钮」这个交互——长单号和商户名对齐很难看，y/n 也快不起来。
所以做成了一个**本地网页**：一次只出一笔，两笔交易左右并排，**差异字段高亮**，
下面两个大按钮：

```
[ 1  是同一笔          ]    [ 2  是两笔独立交易   ]
   从统计里剔除这一笔           保留两笔，以后不再提示
```

键盘 `1` / `2`（或 `←` / `→`）即可，手不用离开键盘。审完自动关服务。

**触发方式有两个：**

- 交互式跑 `monthly` 时发现疑似重复 → **自动拉起**（不用另敲命令）
- 手动补跑：`python -m importer review --ui`

两者用的是同一份账本连接。自动拉起发生在账本加密落盘**之前**，
所以界面里的裁定会跟这次导入的结果一起写进 `ledger.db.enc`。

安全上：

- **只绑 `127.0.0.1`**，局域网访问不到；代码里直接拒绝绑定其它地址
- URI 里带一次性随机令牌，本机其它进程猜到端口也动不了你的账本
- 页面完全自包含，**不引任何外部资源、不联网**
- 不落任何文件，页面是现生成的

两个按钮都只改数据库里的 `review` 标记，**不删除任何记录**：
`confirmed_dup` 从统计里剔除（原始行仍在库里），`confirmed_ok` 以后不再提示。

### 7.8 为什么不用 AI agent 做这件事

整条流水线只需要几秒，全程离线。让一个 AI 会话每天启动来做它，只多耗电、不多出任何价值。

**AI 在这条链路里只出现在一个位置：商户名 → 消费分类的兜底**，而且：
- 得手动加 `--ai` 才启用（默认关闭）
- 必须插电（`power.py` 拦截）
- 结果写进 `merchant_category` 缓存，同一个商户只问一次

绝大多数月份，规则 + 缓存就能覆盖全部流水，一次模型都不用调。

**修掉的问题**（都是实测撞出来的，分批记录）：

*第一批（导入器）*

1. `--vault` 只换了 vault、没换数据库路径——数据库仍写死指向默认 vault。
   表现是「测试参数看着生效了，数据却写进了真实账本」。数据库路径一律由 vault 推导。
2. `inbox\说明.txt` 被当成账单文件，每次运行都多报一条失败，把真正的失败淹掉。
   `.txt` 已从识别后缀里去掉，说明文件单独排除。
3. `password set` 在非交互终端下**直接卡住**：Windows 的 `getpass` 走 `msvcrt`
   读控制台，不看 stdin，管道输入喂不进去。已加 `isatty()` 前置判断。
4. 报表前多打了一行分隔线（重复输出）。

*第二批（加密存储 + 网页界面）*

5. **从 WAL 明文库迁移时，`deserialize()` 必然把连接搞坏。**
   WAL 模式库 `serialize()` 出来的镜像，文件头读写版本字节仍标着 WAL；
   装进内存库后 SQLite 去找不存在的 `-wal` 文件，**每一个查询都报
   `unable to open database file`**。阴险的地方是 `deserialize()` 本身不报错，
   错误延迟到第一次查询才出现。修法：序列化前先 `PRAGMA journal_mode = DELETE`。
   纯内存往返不会触发，所以第一轮测试全绿、只有迁移路径炸。
6. **`disable_journal_mode` 顺带修掉一个数据丢失隐患**：不 checkpoint 就 serialize，
   会丢掉 WAL 里尚未并回主库的那部分数据。
7. **网页界面跨线程用 sqlite 连接**：`ThreadingHTTPServer` 每个请求开新线程，
   而连接建在主线程，Python 默认禁止跨线程使用，点一次按钮就抛
   `SQLite objects created in a thread can only be used in that same thread`。
   修法：`check_same_thread=False` + 一把锁守住所有账本操作。
8. 去掉了「保存 zip 密码」的全部代码路径——**不给的能力就不会被误用**。

## 9. 明确不采用的做法

| 做法 | 为什么不用 |
|---|---|
| 用 AI 判断重复 | 不可复现、不可解释，误删时无从追查 |
| 自动合并跨渠道重复 | 会误删真实消费 |
| 写死列号解析 | 改版后静默错位，把金额读到备注列 |
| 云端 OCR / 云端分类 | 账单数据一旦离开机器就不再受你控制 |
| 用 openpyxl 等第三方库读 xlsx | 多一个依赖多一份供应链风险；xlsx 是 zip+XML，标准库够用 |
| 明文存原始账单 | 原始文件归档进 vault，跟账本同一个安全区 |
| 导入时不校验笔数 | 残缺文件会静默记成「本月零支出」 |
| **保存账单 zip 密码** | 你要求用完即忘。代码里干脆不提供这个能力，不给就不会被误用 |
| **自己写 AES 加密数据库** | 密钥还是得存在同一台机器上，等于没加密。用系统提供的 DPAPI |
| **运行时解密数据库到临时文件** | 会在硬盘上留下明文副本，恰好是要防的东西。改成全程内存 |
| 把 review 界面做成需要联网的网页 | 只绑 127.0.0.1、不引外部资源、不落文件 |
